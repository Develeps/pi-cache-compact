# pi-cache-compact

Расширение [pi](https://github.com/earendil-works/pi) (coding agent): **компактация контекста с переиспользованием prompt cache** локального LLM-сервера (llama.cpp, OpenAI-совместимый `/chat/completions`).

## Зачем

Штатный compact в pi делает отдельный запрос на саммаризацию с **другим system prompt** — он не пересекается с KV-кэшем живой сессии. На локальном сервере это означает **холодный препилл всего контекста** (сотни тысяч токенов по ~700 t/s = несколько минут), хотя тот же самый префикс уже посчитан и лежит в prompt cache.

Расширение перехватывает compact и выполняет саммаризацию **реплеем последнего захваченного запроса** (побайтово идентичный префикс) на тот же сервер: препилл занимает секунды (а при полном хите — доли секунды), остальное время — только генерация саммария.

## Как это работает

1. **Захват.** Хук `before_provider_request` (только main-сессия) хранит последний запрос как есть: model, baseUrl, заголовки (включая Authorization), JSON-тело (system + tools + messages).
2. **Триггер.** Хук `session_before_compact` срабатывает **только на ручном `/compact`** (`reason === "manual"`).
3. **Реплей.** Тело копируется, добавляется одно instruction-сообщение («сверни сессию по схеме ## Goal / Decisions / Progress / …»), `stream=false`, `max_tokens ≥ 8192` (защита от обрыва саммария), и POST в `{baseUrl}/chat/completions` того же сервера.
4. **Гарант качества.** Ответ проверяется: пустой `content` (маленькие модели тратят бюджет на скрытый reasoning) → повторный запрос ×2; «эхо» последнего сообщения (prefill без генерации) → отклонение. При отклонении — **тихий fallback** на штатный compact pi.
5. **Компакт всегда происходит.** Любая ошибка хука (нет захвата, сервер недоступен, модель сменилась, fallback) → pi делает обычный compact. Расширение только ускоряет, никогда не блокирует.

После компакта pi шлёт обычный следующий запрос — сервер добирает хвост (саммарий) и переиспользует тот же слот (`f_sim_best ≈ 0.98–1.0`), живая сессия не «ломается».

## Требования

- pi (расширения в `~/.pi/agent/extensions/`).
- OpenAI-совместимый локальный сервер с prompt cache: `llama-server` (llama.cpp) с `--cache-ram` (ring) и одним слотом. Модель — какая угодно, поддерживающая `/chat/completions` с `usage.prompt_tokens_details.cached_tokens` (llama.cpp отдаёт её).
- Сессия должна работать на этой модели: реплей идёт в тот же `baseUrl` с тем же `model`, что и последний запрос.

## Установка

```bash
cp cache-compact.ts ~/.pi/agent/extensions/
# в pi: /reload
```

## Команды

| Команда | Действие |
|---|---|
| `/compact` | Ручная компактация. С расширением — через кэш (уведомление `cache-compact ✓: cached 120.9k / fresh 0.0k (100% hit, 110.3s)`). Без захвата/при сбое — штатная. |
| `/cache-compact auto` | Режим по умолчанию: перехват **включён с начала сессии и после каждого `/reload`**; в начале сессии показывается баннер `cache-compact: enabled — …`. |
| `/cache-compact on` | Включить прямо сейчас (баннер сразу). |
| `/cache-compact off` | Выключить: `/compact` идёт штатным путём. Состояние в памяти процесса — после `/reload` снова `auto`. |
| `/cache-compact status` | Режим (auto/on/off) + что захвачено (model, кол-во сообщений, ~токены, возраст) + метрики последнего реплея. |

Хук перехватывает любой компакт, кроме `overflow` (там полный реплей может не влезть в окно — штатный путь сам отрезает хвост).

**Баннер.** При включённом режиме (auto/on) в начале сессии (и после `/reload`) расширение показывает строку `cache-compact: enabled — /compact replays the captured request through the server's prompt cache` — признак того, что функция активна именно в этой сессии.

## Чтение логов llama.cpp (как убедиться, что сработало)

Для задачи компакта (`/compact`):

- `[slot] prompt eval time = 0.3 s / 4 tokens` — препилл только «хвост» (добавленное instruction-сообщение / вытесненный фрагмент), а не весь контекст. **Мало = хит.**
- `[slot] prompt cache lookup: f_sim_best = 1.000, f_keep = 0.998, matched M/N` — слот выбран по LCP, почти всё совпало.
- `[slot] gen time = 110 s / 4427 tokens` — генерация саммария (~40 t/s на референсном железе).
- `total time` ≈ время, которое вы ждали `/compact`.

Для сравнения штатный (холодный) compact той же глубины: `prompt eval time = 170+ s / 118k tokens` + генерация = **5–7 минут**.

## Ограничения и тонкости

- **Ротация ring.** `--cache-ram` ограничен (в наших замерах ~3 ГБ): при давлении llama.cpp вытесняет старые записи (`[srv alloc] making room for prompt cache entry, removing oldest entry`), и хит становится частичным (92–99.3%). Это всё равно на порядок быстрее холодного пути; для ~120–200k контекста увеличьте `--cache-ram` (например, 6–8 ГБ) или уменьшите `--ctx-size`-зависимые расходы.
- **Одна модель на сессию.** Если вы переключили модель (`/model`) — захват устарел, хук тихо вернётся на default compact.
- **Маленькие модели** (≤27B без хорошего reasoning-контроля) изредка деградируют: пустой ответ или «эхо». Retry ×2 + guard ловят это, цена fallback'а — один холодный препилл. На API-моделях (Claude и др.) ветка реплея не используется (разные форматы провайдера) — работает штатный compact.
- Захваченные заголовки с Authorization используются только для запроса к **тому же локальному серверу** (не покидают машину).

## Замеры (одна сессия, Qwen3-27B, GGUF, CPU+GPU, spec-draft, ring 3 ГБ)

| Компакт | Контекст | Путь | Hit | Препилл | Итоговое время |
|---|---|---|---|---|---|
| C0–C2 | 49–186k | default (холодный) | 0.1–16.3% | 140–250 s | ~6.5–7.5 мин |
| C3 | 62k | hook | 92% | 5 s | ~40 s |
| C4 | 81k | hook | 99.3% | 5 s | ~2.1 мин |
| C5 | 147k | hook | 98.5% | 4.8 s | ~2.9 мин |
| C6 | 118k | hook | **100%** | **0.26 s** | **~1.8 мин** |

Ускорение: **~2.4–3.8×**, растёт с глубиной контекста (прямой препилл — линейная доминанта).

Качество саммария проверено соак-тестом: в контекст вставлялись три «фикстуры» по ~43k токенов с контрольными суммами; после двух последовательных компактов новый саммарий **слиял** предыдущий саммарий с новым материалом (цель, решения, все чексама фикстур на месте, структура `## Goal/…` сохранена, «эхо» отсутствует), хвост контекста сохранён дословно через `firstKeptEntryId`.

## История создания

Проект рождён в диалоге с локальной моделью — по традиции ИИ-сотрудничества идея была предложена qwen3.8-27b, а затем вдвоём (пользователь + модель в pi) построена, замерена и доведена до результата.

**Боль.** В длинных сессиях компактация каждый раз «сбрасывала» prompt cache локального сервера: штатный compact собирает запрос с *другим* system prompt (сериализованный транскрипт) — ноль попадания в кэш, полный препилл 100k+ токенов и несколько минут ожидания на каждом компакте.

**Осознание.** Если модель сама по себе умная — зачем добавлять в начало сессии особый промпт для компакции? Послать ровно тот же запрос (побайтово идентичный префикс — он уже посчитан и лежит в кэше) и добавить **на конец** одно instruction-сообщение «сверни». Препилл: секунды (или доли секунды) вместо минут.

**Железо и скорости** (референс, на котором делались все замеры): одна RTX 3090 + 32 ГБ DDR3-1600 в системной памяти. Локальный сервер llama.cpp «dflash2» (speculative draft/MTP + flash attention). Генерация: 60–70 ток/с на маленьком контексте, 28–39 ток/с у предела окна; код генерировался быстрее «размышлений» (при 180k контекста написание кода — 35–41 ток/с). Видение в проект не попало: в сборке модели vision-часть «сплетена» с draft/MTP-модулями (dflash2) — включённый dflash2 уносит vision за собой, вместе они не работают (по отдельности — работают). Поэтому модель разбита на два билда: **Coder** (dflash2, текстовый — на нём сделаны все замеры) и **Vision** (без dflash2, с видением).

**Результат.** Компакт стал быстрее в 2.4–3.8× (разрыв растёт с глубиной контекста), хвост сессии сохранён дословно, саммарий — с корректным слиянием предыдущих, а безопасность тривиальна: любой сбой → штатный compact pi, контекст сжимается всегда. В итоге проект выдался очень хорошим — он ощутимо увеличил скорость работы с моделью.
